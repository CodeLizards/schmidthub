Working assumption

~25 productive hours a week × ~1.5× AI assist on well-scoped work — averages to roughly the equivalent of one full-time engineer on a good week, less on ambiguous ones. AI is not a multiplier on decisions or on debugging integration glue between Next.js and the inherited Python backend. About one week of the twelve is real buffer; use it on polish, not new scope.

What one person + AI builds, and what waits.

Everything still on the “Out” list is deferred, not dropped: the data model is drawn as if those surfaces existed, so wiring them up post-pilot is UI work, not a rewrite.

The inherited codebase

Extend what you inherit; don’t rebuild it.

You’re inheriting on both sides: a Next.js frontend with real public content pages, and a Python backend on Postgres with Alembic migrations already in place. The rule below: extend what has real shape, rewrite what doesn’t, and don’t re-solve problems the previous developer already solved.

LayerDefault callTrigger to reconsider
Content pages (FE) Keep in place, re-skin to tokens Only rewrite if they use an old Pages Router API you don’t want to carry.
App shell (FE) Adopt if App Router; wrap if Pages Router Whichever router the content pages use is the router the whole app uses.
Design tokens Extract from existing pages first If ad-hoc, define your own and re-skin inherited pages to match.
Postgres schema Keep what exists; add via new Alembic revisions Only rewrite a table if the current shape actively blocks the wireframe spec.
Backend framework Keep whatever’s there (FastAPI / Flask / Django) Only re-platform if there’s no working request path at all.
Auth If backend has session/JWT wired, extend it. Else add Clerk (frontend) or magic-link on the backend. Rewriting inherited auth in W1 has eaten many pilots. Avoid unless truly broken.
Dependencies Audit both lockfiles (pnpm + Python); upgrade before touching code Stale Python deps + old Alembic revs are where a lost weekend hides.
Decisions needed in W1

Two calls to make on day two: (1) which Python framework (FastAPI is the assumption baked into the plan below; Flask/Django costs 1–2 days extra to learn if new to you); (2) which Next.js router (App Router preferred, but follow whichever the content pages use). Auth is not a W1 decision anymore — the pilot runs on a shared basic-auth gate + pick-a-user dropdown (see Stack), with real auth deferred until post-demo.

Recommended stack

Solo tools: extend inherited, add only what you must.

Two-target stack: a Next.js frontend deploying to Vercel, and the inherited Python + Postgres + Alembic backend deploying to Fly.io (or wherever it already runs). The list below is what the plan below assumes; confirm each row in W1.

LayerChoiceWhy this and not the alternative
Frontend Next.js 15 · TypeScript · router TBD in W1 App Router preferred; inherit whichever the content pages use so you’re not straddling both.
Backend Python · framework TBD, assume FastAPI Inherited. FastAPI is the assumption; Flask/Django would cost a couple of days to acclimate.
Database Postgres (inherited) Already there. Managed instance: Neon or Supabase Postgres — pick whatever the previous dev used.
ORM + migrations SQLAlchemy 2.0 + Alembic (inherited) Extend the existing model classes; every schema change is a new Alembic revision.
API contract FastAPI OpenAPI → typed client via openapi-typescript One schema, two languages. Frontend never invents types the backend doesn’t bless.
Auth (pilot) Pick-a-user dropdown + shared basic-auth gate The wireframes’ demo bar is this pattern. One shared password to enter the pilot, then a signed cookie stores user_id. Buys ~4 days back into W2 for schema reconciliation.
Auth (post-pilot) Clerk (FE) or magic-link (BE) Swap in as a scoped ~1 week task before real users get accounts. Do not ship the pilot pattern to production.
Storage S3-compatible object store · Cloudflare R2 Cheap, no egress fees. Direct-to-storage signed uploads via a backend endpoint that returns a presigned URL.
UI Tailwind + shadcn/ui, custom tokens Ships fast, overridden with a SHIP-specific token layer so it doesn’t read as generic.
Forms & validation React Hook Form + Zod Zod schemas mirror the OpenAPI types; wizard drafts are just a partial parse.
Search Postgres ILIKE + pg_trgm index Enough for a few dozen seeded entries. Full-text is a swap-in later; no schema change.
Error tracking Sentry on both FE and BE Solo means silent failures cost you a week. Wire it W1 on both sides, keep it wired.
Hosting & CI Vercel (FE) + Fly.io (BE) + GitHub Actions Two deploys; both PR-preview capable. Pilot URL fixed from W8 onward.

Risks worth naming

Six things most likely to eat the twelve weeks.

R1 · Solo capacity, AI-shaped
AI speeds the well-scoped, not the ambiguous.

AI is a real multiplier on wiring code from clear specs and near-zero on debugging integration glue or making architectural calls. Mitigation: spend the AI budget on the middle third of the week (build), not Monday (plan) or Friday (self-demo & decisions).

R2 · Scope
The wireframes cover triple this scope.

Every deferred surface will get asked for. The “Out” list is signed at kickoff and re-shown at every gate; new asks trade against something already In, one-for-one.

R3 · No code review
Nobody catches your bad Tuesday.

Mitigation: types + Zod at every boundary; a small Playwright smoke test on the demo script from W6 that runs on every deploy. Sentry wired since W1.

R4 · Data credibility
Seed data that doesn’t match the tiles.

Benchmarks are computed from seeded events, not hardcoded; every review and download in the seed is a real row. Reset in one command.

R5 · Pilot recruit
Real pilot users won’t materialise on time.

Start pilot recruit in W2, not W10. Five confirmed users by end of W6 is the internal gate; anyone missing gets a stand-in account you drive yourself.

R6 · Uploads
File handling always takes longer.

500 MB cap in the wireframes is real work; you’re shipping 50 MB and telling the pilot so. Direct-to-storage signed uploads only.

R7 · Inherited codebase
The backend is where the hidden work lives.

Stale Alembic revisions, half-implemented models that disagree with the wireframes, and dead auth code all cost days apiece. Mitigation: W2 reconciles the schema explicitly (diff written down), OpenAPI is the contract, and Sentry is wired to both sides from day one.

Cut list · in order

What to drop if the W6 gate misses by more than a week.

The In-list is honest but ambitious. If you’re behind at G2 (end W6), apply these cuts before starting W7 — not after. Defending the full list into W10 and rushing the pilot is the failure mode this list exists to prevent. None of these cuts break the demo loop.

  1. Audit log viewer Events keep being written to AuditEvent; no UI to browse them. Query directly from Postgres when needed. Costs: one screen in Super Admin. Demo beat swaps to an SQL query on screen.
    ~4 days
  2. Legal Reviewer as a distinct role Collapse back to a routing state on Reviewer. Same UI, filter by legal_pending. Emma logs in as a Reviewer and reads the queue. Costs: no separate sidebar. State machine and audit trail are unchanged.
    ~4 days
  3. In-app message relay Replace “Contact IP holder” with a form that opens a mailto: to the submitter’s address. Keep the intent, drop the thread. Costs: no in-app inbox thread. Notifications for messages disappear.
    ~4 days
  4. Notifications inbox Keep the badge count on the top bar; click routes to My Submissions filtered to items with new activity. No dedicated list. Costs: less polish on the notifications story. State-change awareness is preserved.
    ~2 days
Apply top-to-bottom, one at a time, until you’re back on schedule Total headroom · ~14 days

Fifteen minutes, one loop, one message per beat.

  2. Beat · PublicOpen the Coral Reef Bleaching dataset. Walk description, gallery, license (CC BY 4.0). Click Download — accept the license in the brief form — file downloads with a signed URL.
